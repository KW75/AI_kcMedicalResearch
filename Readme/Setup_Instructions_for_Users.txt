AI kcMedicalResearch - Setup Instructions for Users
Version 2.4.7 | 2026-08-17


============================================
Option 1: Use the Web App (No Install)
============================================

Live Web App:  https://ai-kcmedicalresearch.onrender.com
Health Check:  https://ai-kcmedicalresearch.onrender.com/_stcore/health

Open the link in any browser. No Docker, no Python, no setup, no API key.
First load may take ~30 seconds if the service was asleep.

This is the right choice for most people. Use Option 2 only if you need to
process your own PDFs locally, or need to work offline.

Note: the hosted app does not include the RAG / embedding features, and the
systematic review pipeline is best run locally where its interactive prompts
have a real terminal.


============================================
Option 2: Run Locally with Docker
============================================

You need: Docker Desktop, and an API key for at least one provider.

    Docker Desktop
        Windows / macOS : https://www.docker.com/products/docker-desktop
        Linux           : https://docs.docker.com/engine/install/

    API keys - you need your OWN. Keys are never included in the image.
        DeepSeek (default, cheap)     https://platform.deepseek.com
        Qwen / DashScope (needed for  https://dashscope.aliyuncs.com
          the SR pipeline - vision)
        Groq (free tier, optional)    https://console.groq.com

    Set a spending limit in each provider's console.


Step 1 - Get the code

    git clone https://github.com/KW75/AI_kcMedicalResearch.git
    cd AI_kcMedicalResearch


Step 2 - Create your .env

    Windows:      copy .env.example .env
    macOS/Linux:  cp .env.example .env

    Then open .env in a text editor and fill in the keys you have.
    At minimum set DEEPSEEK_API_KEY, plus DASHSCOPE_API_KEY if you want to
    run systematic reviews.

    IMPORTANT - no quotes around values:
        correct    DEEPSEEK_API_KEY=sk-abc123
        wrong      DEEPSEEK_API_KEY="sk-abc123"
    Docker passes the quotes through as part of the key.

    .env stays on your machine. It is excluded from git and from the Docker
    image, so your keys are never shared.


Step 3 - Run

    From the docker/ folder:

        cd docker

    Interactive CLI menu (all six pipelines):

        docker compose run --rm cli

    Streamlit web UI, then open http://localhost:8501:

        docker compose up ui

    Stop the UI with Ctrl+C.

    The first run builds the image and takes 5-10 minutes. Later runs start
    in seconds.

    After pulling code changes, rebuild:

        docker compose build


Where your files go
-------------------

    Put input files in    input/<mode>/     e.g. input/sr/ for review PDFs
    Results appear in     output/<mode>/
    Full audit trail in   reports/

    These folders are mounted into the container, so files you add on your
    machine appear inside it immediately, and results are written back out.


============================================
Option 3: Run Locally without Docker
============================================

For developers. Needs Python 3.11 or 3.12.

    NOTE: Python 3.13 and 3.14 are not currently supported. Several pinned
    dependencies do not build on them. If python.org offers only a newer
    version, use Option 2 (Docker) instead - Docker supplies its own Python
    and ignores whatever you have installed.

    git clone https://github.com/KW75/AI_kcMedicalResearch.git
    cd AI_kcMedicalResearch

    python -m venv .venv
    .venv\Scripts\activate            # Windows
    source .venv/bin/activate         # macOS/Linux

    pip install -r requirements.txt

    copy .env.example .env            # then add your keys

    python scripts/launcher.py        # menu
    python SOURCE_CODE/main.py        # direct

    Startup takes about 7 seconds while dependencies load.

Optional OCR support (scanned PDFs, legacy .doc)

    pip install -r requirements-ocr.txt

    This also needs system binaries that pip cannot install:

        Tesseract  Windows: https://github.com/UB-Mannheim/tesseract/wiki
                   macOS:   brew install tesseract
                   Linux:   sudo apt-get install tesseract-ocr

        Poppler    Windows: https://github.com/oschwartz10612/poppler-windows/releases
                   macOS:   brew install poppler
                   Linux:   sudo apt-get install poppler-utils

    Then set TESSERACT_PATH and POPPLER_PATH in .env.
    Without OCR the app runs normally and reports OCR as unavailable.


============================================
Providers
============================================

Default is DeepSeek. On transient errors (timeout, 429, 502, 503) the app
automatically tries the next provider in FALLBACK_PROVIDERS
(default: deepseek,qwen,groq). Authentication errors do not fall back.

Override per run with --provider:

    python SOURCE_CODE/main.py --mode writing --provider groq

Systematic review needs a vision-capable provider: qwen, openai, anthropic
or groq. DeepSeek and Ollama cannot do SR.

Qwen uses two models: QWEN_MODEL (qwen-plus-latest) for text, and
QWEN_VISION_MODEL (qwen-vl-max) for SR page images. SR selects the vision
model automatically; no --model flag needed.


Local AI with Ollama (free, offline, optional)
---------------------------------------------

    Install: https://ollama.com/download
    Pull a model:  ollama pull llama3.2

    python SOURCE_CODE/main.py --provider ollama

    The app auto-detects the best installed model.

    Limitations: slow with large models, frequent timeouts on the coding and
    writing pipelines, and no vision - so Ollama cannot run SR.

    In Docker, the container reaches Ollama on your machine via
    host.docker.internal; docker-compose.yml already sets this.


============================================
Systematic Review Pipeline - READ FIRST
============================================

Before using SR output in an actual review, read:

    Readme/REVIEWER_GUIDE.md

Extraction is LLM-based and cannot verify its own semantics. It will produce
a confident, precisely-quantified effect size whether or not it understood
the paper. Two failure modes are documented and unfixed:

    - a reported standard error can be read as a standard deviation
    - a within-subject before/after change can be extracted as though it
      were an intervention-versus-control comparison

Both have been observed producing a large, entirely invalid effect size that
passed every stage of the pipeline without a warning.

Extraction is also non-deterministic: the same PDF can yield different
numbers on consecutive runs.

Therefore: every mean, SD and sample size must be checked against the source
PDF before any pooled estimate is reported. Reviewer-verified corrections go
in input/sr/study_overrides.yaml, and every one is logged so it can be
declared in your methods section.

Run SR directly rather than through a menu, so the interactive PICO prompts
get a real terminal:

    python SOURCE_CODE/main.py --mode sr --provider qwen


============================================
Troubleshooting
============================================

Docker not found            Install Docker Desktop
Docker not running          Start Docker Desktop and wait for the whale icon
Build fails                 Check your internet connection; retry - transient
                              PyPI failures are common
Port 8501 in use            Another instance is running; stop it or open
                              http://localhost:8501
UI shows a blank page       Wait ~15 seconds and refresh; the server starts
                              after the container does
Auth error from provider    Check .env has no quotes around the key value
Ollama unreachable          In Docker use host.docker.internal, not localhost
SR extracts nothing         Use a vision provider (qwen). DeepSeek cannot
                              read page images
pip install fails           You are probably on Python 3.13+. Use Docker
Python 3.11 unavailable     Use Docker; it supplies its own Python
