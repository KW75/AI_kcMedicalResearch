Systematic Review Pipeline
--mode sr
⚠️ Read REVIEWER_GUIDE.md before using SR output in a review.
Extraction is LLM-based and cannot verify its own semantics. It emits a confident, precise effect size whether or not it understood the paper. Plausibility is not evidence of correctness. Every mean, SD and N must be checked against the source PDF before any pooled estimate is reported.
Known blind spots
GapConsequence
CRITICAL SD vs SE not distinguishedA reported SE read as an SD understates dispersion by up to √n and inflates the effect size
CRITICAL Within- vs between-group not detectedA pre/post contrast can be extracted as intervention-vs-control, giving a large invalid effect with no warning
HIGH Extraction is non-deterministicSame PDF can yield different means/SDs/Ns across runs. Run 3× and diff before trusting output
MED No plausibility bound|g| > 1.5 from a psychotherapy trial passes unflagged

Vision model
💡 SR uses QWEN_VISION_MODEL (default qwen-vl-max) automatically. The Qwen text model qwen-plus-latest is text-only and cannot extract from page images. No --model flag needed.
Study metadata & manual overrides

Metadata resolves in three stages, each overriding the last:

#SourceFlagged as
1Extraction model output—
2Derived from the PDF (metadata, DOI, copyright year)pdf_auto (verify)
3Reviewer overrides — input/sr/study_overrides.yamloverride_fields
"some_paper.pdf":
  first_author: Nguyen
  year: 2021
  n_intervention: 42
  n_control: 40
  mean_intervention: 4.10
  sd_intervention: 1.85
  note: "Table 2, 12-week endpoint. Verified from PDF p.7."

Metadata fields fill only when blank. Numeric fields replace extraction output. Extraction still runs in full, so the log reports:

Log entryMeaning
field(7.32->7.35)Extraction was wrong; override corrected it
field(confirmed 7.35)Extraction independently agreed — a real cross-check
field(absent->7.35)Extraction produced nothing for this field
💡 End of Stage 3 prints a DATA PROVENANCE SUMMARY listing every study using overrides or auto-derived metadata. Both must be described in the review's data-collection methods.
⚠️ Overrides affect extraction and meta-analysis only. Screening and RoB 2.0 re-read the PDF independently.
Reviewer rules
#Rule
1Read the source table first. Never enter a value inferred from what the pooled estimate "should" look like
2Always fill note with table number, page, and date
3Verify symmetrically — checking only studies that surprise you introduces selection bias
4Never edit the override file after looking at the forest plot
5Overrides are data, not code — commit them with a message explaining the verification
Recommended workflow
StepAction
1Run --mode rct_search -> get ranked articles
2Review output/rct_search/rct_search_*.docx
3Download PDFs, place in input/sr/
4Run python SOURCE_CODE/main.py --mode sr --provider qwen (run directly, not via the menu launcher, so PICO prompts get a real TTY)
5Verify every included study against its source PDF; record corrections in study_overrides.yaml
6Re-run 3× and diff meta_analysis_results.csv before reporting

Fallback Chain
💡 On transient errors (timeout, 429, 502, 503), the system automatically tries: DeepSeek -> Qwen -> Groq. Auth errors (401, 403) raise immediately. Configure via FALLBACK_PROVIDERS env var.
Streaming

All providers support live token streaming. Enabled by default. Use --no-stream to disable. Non-TTY environments (pipes, CI) automatically use batch mode.
