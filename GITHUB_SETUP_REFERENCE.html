GitHub Setup Reference

Project: 
D:\ai-automation-tool

Scope of this reference

This reference summarizes the steps completed after the previous Ollama handoff, up to creation of the empty GitHub repository.

Current stop point:

Local Git repository exists.
First local commit exists.
Branch is named main.
Empty GitHub repository exists.
Remote has not been added yet.
Code has not been pushed yet.

Important user rule

Proceed one step at a time. Do not continue to the next step until the user says OK.

Steps completed

1. Reopened VS Code and reactivated the virtual environment

When VS Code was reopened, the terminal no longer showed (.venv). This is normal.

cd D:\ai-automation-tool
.\.venv\Scripts\Activate.ps1

Function:

  • Moves into the project folder.
  • Reactivates the Python virtual environment.

Expected prompt:

(.venv) PS D:\ai-automation-tool>

2. Verified previous handoff files

dir HANDOFF.*

Function: checks that the previous handoff files exist.

Expected files:

HANDOFF.md
HANDOFF.html

Optional:

Start-Process .\HANDOFF.html

Function: opens the HTML handoff file in the browser.

3. Checked Git installation

git --version

Function: confirms Git is installed and available in PowerShell.

4. Checked Git identity settings

git config --global user.name
git config --global user.email

Function: checks the name and email Git will attach to commits.

Initial result:

  • Values were blank.
  • Placeholder values were accidentally saved.
  • They were later corrected.

5. Set Git name and email

git config --global user.name "Your GitHub Username Or Name"
git config --global user.email "your-github-email@example.com"

Function: sets the global Git identity used when making commits.

user.name is not the repository name. It is the person or username making the commit.

Repository name remains:

ai-automation-tool

Verification:

git config --global user.name
git config --global user.email

6. Initialized Git locally

git init

Function: creates a local Git repository inside the project folder.

7. Checked Git status before committing

git status

Short version:

git status --short

Function:

  • Shows which files Git sees.
  • Helps confirm private files are ignored.

These should not appear:

.env
.venv/

This is safe to appear:

.env.example
.env and .venv/ are file/folder names to check inside Git status. They are not commands to run.

8. Added project files to Git

git add .

Function: stages all non-ignored project files for the first commit.

Then checked again:

git status --short

Function: confirms which files are staged and confirms .env and .venv/ are not staged.

9. Made the first local commit

git commit -m "Initial local Ollama AI automation tool"

Function: saves the current project state into Git history.

Then checked:

git status

Expected result:

nothing to commit, working tree clean

10. Renamed branch to main

git branch -M main

Function: renames the current branch to main.

Verification:

git branch --show-current

Expected output:

main

Commit verification:

git log --oneline -1

Expected result includes:

Initial local Ollama AI automation tool

11. Created empty GitHub repository

GitHub page used:

https://github.com/new

Repository settings:

Repository name: ai-automation-tool
Visibility: Private

These boxes were not checked:

Add a README file

Reason:

  • The local project already has files.
  • The local project already has .gitignore.
  • The first push should go from the local project to the empty GitHub repo.
